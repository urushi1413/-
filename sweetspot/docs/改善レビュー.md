# SWEET SPOT 辛口レビューと改善案 100

- 対象：`sweetspot/`（コミット d3eb4c1、2026-11-17 時点）
- 書いた人：Claude（厳しい Steam レビュアーとして）
- 使い方：1 章が感想、2 章が改善点 100、3 章が順位、**4 章が上位 20 の実装の指示書**（Fable がそのまま作業できる細かさ）

## 0. 何を見て書いたか

- Linux で raylib 5.5 を入れてビルドし、画面のない環境（Xvfb）で実際に動かして画面を撮った：タイトル → 選手と試合 → 試合（自動操作 B で 1 試合）→ 試合の結果 → 一時停止 → はじめての人へ → ラリー練習（自分で打った）→ グランドスラムの組み合わせ表
- `make sim`（AI 同士の試合）を、そのままと、**打ち切り時間を 30 秒 → 300 秒に延ばして打ち切りを数える版**の両方で回した
- コード（main.c・ai.c・tour.c・score.c・input.c・playlog.c ほか）と README・開発メモ・ストアの下書きを読んだ
- 音は出せない環境なので、音の評価は README とコードから推測した部分がある

数字の根拠になった計測：

| AI 同士（各 200 ポイント） | 元のツール（30 秒で打ち切り）の平均ラリー | 打ち切り 300 秒の平均ラリー | 300 秒でも終わらなかったポイント |
|---|---|---|---|
| EASY（ハード） | 4.8 打 | 5.1 打 | 0% |
| NORMAL（ハード） | 4.7 打 | **25.1 打** | 0% |
| PRO（ハード） | 2.1 打 | **97.2 打** | **17%** |
| PRO（芝） | 1.2 打 | 86.7 打 | 18% |

元のツールは 30 秒で打ち切ったポイントを「手前の選手の勝ち」にし、その打数を平均に入れていない。README の「PRO 同士の平均ラリー 4.4 打」などはこの数字なので、**今のバランスの議論の土台が崩れている**。

## 1. Steam レビュー（辛口）

> 👎 **おすすめしません（今は）**
>
> 物理と打点の作り込みは、インディーのテニスゲームとして頭ひとつ抜けている。回転で曲がる球、コートごとに変わる弾み、フォアとバックの性格の違い、選手ごとのルーティンや崩れ方。作者がテニスを本気で好きなのは 5 分で分かる。芯を食ったときの金色の軌跡は確かに気持ちいい。
>
> ただ、**最初の 30 分が苦行**だ。初期設定は AI「やさしい」なのに難しさは「リアル」。開発者自身の試算でも普通の人の打球は 3 割しか入らない設定で、ゲーム内の自動操作（B）ですら、初期設定の「やさしい」相手にタイブレーク 3-7 で負けた。最初の試合で負ける体験しか用意されていない。
>
> 画面は文字だらけだ。下には全操作を 1 行に詰めた小さな説明が 3 行、左上には「タイミング +2 度（+158 ms）良い 45%」「step -0.0 m/s」「Net clearance +0.77 m」。開発者の計測パネルをそのまま遊ぶ人に見せている。失敗の理由を教えてくれるのはありがたいが、度とミリ秒で言われても次の 1 球に活かせない。
>
> カメラは後ろの高い位置に固定で、相手は画面の高さの 3% ほどの小人。打つ形が読めないので、ロブやドロップは見てから反応するしかない。
>
> そしてテンポ。ポイントが終わるたびに 2〜3 秒、ジョコビッチ似の選手は大事なポイントでボールを 14〜19 回つく（README の値）。ときどき観客が静まらず 4 秒待たされる。雰囲気作りとしては分かるが、**飛ばせない**のがつらい。飛ばせるのはチェンジコートだけ。
>
> 一番怖いのは、試合中に G を押すと試合が消えること。グランドスラムの試合中（全豪 1 回戦、対ナダル）に押したら、その瞬間にラリー練習へ切り替わり、試合はなかったことになった。G は移動の WASD と F・H のすぐ隣にある。5 セットマッチの途中でも同じ。1/2/3 も AI の強さを変えてやり直しになる。
>
> 遊び続ける理由もない。勝っても、最速サーブを出しても、何も残らない（保存されるのは設定だけ）。練習モードは球を打ち返すだけで、目標も点数もない。グランドスラムは自分がいつもシードなしなので、初戦の相手が必ずシード選手（自分のときは第 2 シード）。しかも相手の強さは 1 回戦から決勝まで同じなので、山場がない。
>
> 裏側では、作者がバランスを測るために使っているツールが 30 秒でポイントを打ち切っていて、AI 同士だと NORMAL は平均 25 打、PRO は平均 97 打（17% は 5 分たっても終わらない）という「壁」になっていることが隠れている。
>
> 素材は本当にいい。直すべきは物理ではなく、**入り口・テンポ・続ける理由**だ。下の 20 個が入ったら、おすすめに変える。

### 良いところ（ここは削らないで）

- 打点・回転・コートの違いが本当に結果に効く。「なぜ入らなかったか」を物理で説明できるテニスゲームは少ない
- 選手の個性（ルーティン、崩れ方、叩きつけ、勝負強さ）の量と細かさ
- 際どい判定の拡大図、ネットイン、ハト、観客がキャッチ、など「テニスの外」の小ネタ
- 自動操作・撮影モード・試合の記録（matchlog.csv）など、開発の道具が揃っている
- 日本語と英語、キーの割り当て、ブラウザ体験版、スマホ版まである

### 一番の問題（要約）

1. **入り口**：初期設定が「リアル」、初回でもタイトルに放り出される、チュートリアルの後に何も起きない
2. **テンポ**：ポイントの間が長く飛ばせない、ちょうどいい試合の長さがない
3. **続ける理由**：記録も目標も残らない、練習に点数がない、大会に山場がない
4. **分かりやすさ**：数値だらけの画面、失敗の理由が人の言葉でない
5. **事故**：試合中の 1 キーで試合が消える、ブラウザ版は設定を覚えない

### 付け方

## 4. 上位 20 の実装の指示書（Fable 向け）

- 作業は `sweetspot/` で。**1 項目 = 1 コミット**。コミットメッセージは今までと同じく、日本語で「何をどう変えたか」を 1 行で
- 行番号はコミット **d3eb4c1** のもの。ずれていたら、書いてある**文字列**（関数名・コメント・変数名）で探す

  - `make`（警告を増やさない）、`make SALE=1`、`make sim`（AI 同士のツールが壊れていないこと）

  3. `LoadSettingsFile`（118 行）で読む

  5. `if (LoadSettingsFile(&s)) { ... }`（542 行）の中で、Clamp して変数に入れる

**作るもの**：新しいファイル `storage.c`（Makefile の `SRC` に足す。`make`・`web`・`mobile` は同じ `SRC` を使う）
```c
// SWEET SPOT — 保存するファイルを、ブラウザ版ではブラウザの保存場所（localStorage）にも写す
#include "game.h"
#ifdef __EMSCRIPTEN__
#include <emscripten.h>
#endif
// 読む前に呼ぶ：ブラウザ版なら localStorage の中身をファイルに書き戻す（パソコン版は何もしない）
void StoreRestore(const char *file)
{
#ifdef __EMSCRIPTEN__
    EM_ASM({ try { var k = 'sweetspot_' + UTF8ToString($0); var v = localStorage.getItem(k);
                   if (v !== null) FS.writeFile(UTF8ToString($0), v); } catch (e) {} }, file);
#else
    (void)file;
#endif
}
// 書いて閉じた後に呼ぶ：ブラウザ版ならファイルの中身を localStorage に写す
void StorePersist(const char *file)
{
#ifdef __EMSCRIPTEN__
    EM_ASM({ try { var f = UTF8ToString($0);
                   localStorage.setItem('sweetspot_' + f, FS.readFile(f, { encoding: 'utf8' })); } catch (e) {} }, file);
#else
    (void)file;
#endif
}
```
- game.h に `void StoreRestore(const char *file); void StorePersist(const char *file);`
- `SaveSettingsFile`：`fclose(f);` の後に `StorePersist(SETTINGS_FILE);`
- `LoadSettingsFile`：`fopen` の前に `StoreRestore(SETTINGS_FILE);`
- Makefile の `web` と `mobile` の `emcc` 行に `-sEXPORTED_RUNTIME_METHODS=HEAPF32,FS`（今は `HEAPF32` だけ）。`FS` を EM_ASM から使うため
