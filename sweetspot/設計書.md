# SWEET SPOT 設計書（2026-11-17 の変更分）

このブランチで入れた 5 つの変更の、設計上の要点。細かい数字と遊び方は README.md にある。

## 1. 見た目の底上げ（render.c）

- 切り替えは game.h の定数：`FX_SOFT_SHADOW` / `FX_POST` / `FX_BLOOM` / `FX_BALL_TRAIL`（どれも初期値 1。`-DFX_POST=0` でも切れる）
- 効くのは「ふつう」の見た目（`gLook == 0`）だけ。アニメ調・ドット風は今までどおり
- 影：頂点の色だけで描くだ円（`SoftShadow`）。選手は足元の影＋光と反対へ伸びる体の影（`FigureShadow`）。
  ボールの影は真下（落ちる場所を読む手がかりなので、光の向きへずらさない）
- ポスト処理（`PostFxApply`、`PixelEnd` から呼ぶ。HUD より前）：
  - 3D は今までどおり画面に描く（アンチエイリアスを保つため）。描き終えた画面を `glCopyTexSubImage2D` で写し取り、シェーダーを通して描き戻す
  - ブルームは 1/4 → 1/8 の小さな絵でぼかす。全画面で読む絵は 2 枚だけ
  - シェーダーが作れない・画面と描く大きさが違うときは何もしない（今までどおりの絵）
  - 注意：OpenGL の関数を 1 つ自分で宣言している。Windows のビルドは未確認
- 残像：打ってからの軌跡（1/120 秒ごと）の最後の 0.12 秒を、カメラを向く帯に（`DrawBallAfterimage`）。リプレイは `DrawReplayAfterimage`
- 速さ：GPU のない環境でしか測れていない（全部入れて 1 フレーム +5.5〜8.5ms、ブルームは約 1ms）。実機で重ければ `FX_BLOOM` を 0 に

## 2・3. リターン練習＝試合の AI のサーブ（main.c）

- 前の「サーブマシン」（`MachineServe`）はやめた。試合の「AI のサーブ」の処理をそのまま通る
- 共通の関数：`AiServePrep`（サーブ前の儀式と、トスまでの間）、`PointImportance`（ポイントの大事さ）、`AiServe`（球速・回転・コース・フォルト）
- 進み方：`retPhase` = `RET_WAIT`（次を待つ）→ `RET_SERVE`（儀式・トス）→ `RET_LIVE`（球が生きている）
- 練習の中のスコア `retScore`：相手がずっとサーブするゲームのくり返し。リターンが入れば自分、入らない・返せないならサーバーのポイント
- 声は試合と同じ：サーブの前の声、当たる音、フォルト・アウトのコール、ポイントの 1.1 秒後にスコアコール
- わざと試合と違えている所：ラリーにしない（リターンだけをくり返すため）、観客はいない

## 4. 試合の結果の表（main.c）

- `resultUp`（試合の結果・セット間の表）、`summaryUp`（Tab の表も含む）の間は、表にかかる表示を出さない：
  テロップ、左上の説明、下の成績と操作の行、際どい判定の図、（`resultUp` では）右上のスコア表
- 知らせ（トースト）は表の下、紙吹雪は表の後ろ。表には不透明の下地
- Tab の表はスコア表を残して、その左に収める（`DrawMatchSummary` の `rightLimit`）
- K.O. の文字が消えてから表を出す。スマホ版は結果の間、一時停止のボタンだけ

## 5. ぎりぎり届く球を伸びて取る（shots.c・render.c）

- 判定（`EvaluateContact`）：伸びきったときの限界 = ふつうに届く範囲 ＋ 0.5m（ボレー 0.8m）＋ 身長の差 × `STRETCH_PER_CM`。
  185cm でストローク 2.6m、198cm で 2.78m、178cm で 2.50m
- 当たりの質：`STRETCH_Q_NEAR` 0.70 → `STRETCH_Q_FAR` 0.35（どれだけ伸びたか `Contact.stretchK` で変わる）
- 伸びて届く球は、走っていても飛びつかない。飛びつきは伸びても届かない球だけ（頻度は減る）
- 見た目（`DrawFigureBody`）：届かない分だけ腰を球の方へ出し（`stS`）、前足を踏み出し、後ろ足を残し、肩から球まで腕とラケットを伸ばす。
  体の大きさの単位で計算するので、背の高い選手ほど遠くまで届いて見える。戻りは `SwingAnim.lungeDur`（0.6 秒）
- AI 同士の試算（各 3000 ポイント）で、ラリーの長さ・ウィナーの割合・サーバーの勝率は変える前とほぼ同じ
