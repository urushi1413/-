# SWEET SPOT 設計書（2026-11-17 の変更分）

このブランチで入れた変更の、設計上の要点（1〜5 は前回、6〜8 は改善レビューの後に足した分）。細かい数字と遊び方は README.md にある。

## 1. 見た目の底上げ（render.c）

- 切り替えは game.h の定数：`FX_SOFT_SHADOW` / `FX_POST` / `FX_BLOOM` / `FX_BALL_TRAIL`（どれも初期値 1。`-DFX_POST=0` でも切れる）
- 効くのは「ふつう」の見た目（`gLook == 0`）だけ。アニメ調・ドット風は今までどおり
- 影：頂点の色だけで描くだ円（`SoftShadow`）。選手は足元の影＋光と反対へ伸びる体の影（`FigureShadow`）。
  ボールの影は真下（落ちる場所を読む手がかりなので、光の向きへずらさない）
- ポスト処理（`PostFxApply`、`PixelEnd` から呼ぶ。HUD より前）：
  - 3D は今までどおり画面に描く（アンチエイリアスを保つため）。描き終えた画面を `glCopyTexSubImage2D` で写し取り、シェーダーを通して描き戻す
  - ブルームは 1/4 → 1/8 の小さな絵でぼかす。全画面で読む絵は 2 枚だけ
  - シェーダーが作れない・画面と描く大きさが違うときは何もしない（今までどおりの絵）
  - 注意：OpenGL の関数を 1 つ自分で宣言している。Windows のビルドは未確認
- 残像：打ってからの軌跡（1/120 秒ごと）の最後の 0.12 秒を、カメラを向く帯に（`DrawBallAfterimage`）。リプレイは `DrawReplayAfterimage`
- 速さ：GPU のない環境でしか測れていない（全部入れて 1 フレーム +5.5〜8.5ms、ブルームは約 1ms）。実機で重ければ `FX_BLOOM` を 0 に

## 2・3. リターン練習＝試合の AI のサーブ（main.c）

- 前の「サーブマシン」（`MachineServe`）はやめた。試合の「AI のサーブ」の処理をそのまま通る
- 共通の関数：`AiServePrep`（サーブ前の儀式と、トスまでの間）、`PointImportance`（ポイントの大事さ）、`AiServe`（球速・回転・コース・フォルト）
- 進み方：`retPhase` = `RET_WAIT`（次を待つ）→ `RET_SERVE`（儀式・トス）→ `RET_LIVE`（球が生きている）
- 練習の中のスコア `retScore`：相手がずっとサーブするゲームのくり返し。リターンが入れば自分、入らない・返せないならサーバーのポイント。（後で変えた：スコアとテロップは画面に出さず、スコアコールもしない。左右とセカンドサーブを決めるためだけに使う。自分の立つ位置は `HumanReturnPos`（センターから 2.3m）をやめて、AI がレシーブするときと同じ `ReturnPosVs`。restart の時点からその位置）
- 声は試合と同じ：サーブの前の声、当たる音、フォルト・アウトのコール（スコアコールは後でやめた）
- わざと試合と違えている所：ラリーにしない（リターンだけをくり返すため）、観客はいない

## 4. 試合の結果の表（main.c）

- `resultUp`（試合の結果・セット間の表）、`summaryUp`（Tab の表も含む）の間は、表にかかる表示を出さない：
  テロップ、左上の説明、下の成績と操作の行、際どい判定の図、（`resultUp` では）右上のスコア表
- 知らせ（トースト）は表の下、紙吹雪は表の後ろ。表には不透明の下地
- Tab の表はスコア表を残して、その左に収める（`DrawMatchSummary` の `rightLimit`）
- K.O. の文字が消えてから表を出す。スマホ版は結果の間、一時停止のボタンだけ

## 5. ぎりぎり届く球を伸びて取る（shots.c・render.c）

- 判定（`EvaluateContact`）：伸びきったときの限界 = ふつうに届く範囲 ＋ 0.5m（ボレー 0.8m）＋ 身長の差 × `STRETCH_PER_CM`。
  185cm でストローク 2.6m、198cm で 2.78m、178cm で 2.50m
- 当たりの質：`STRETCH_Q_NEAR` 0.70 → `STRETCH_Q_FAR` 0.35（どれだけ伸びたか `Contact.stretchK` で変わる）
- 伸びて届く球は、走っていても飛びつかない。飛びつきは伸びても届かない球だけ（頻度は減る）
- 見た目（`DrawFigureBody`）：届かない分だけ腰を球の方へ出し（`stS`）、前足を踏み出し、後ろ足を残し、肩から球まで腕とラケットを伸ばす。
  体の大きさの単位で計算するので、背の高い選手ほど遠くまで届いて見える。戻りは `SwingAnim.lungeDur`（0.6 秒）
- AI 同士の試算（各 3000 ポイント）で、ラリーの長さ・ウィナーの割合・サーバーの勝率は変える前とほぼ同じ

## 6. 試合の途中は 1 キーで設定を変えない（改善レビュー B04、main.c）

- `matchLive = mode == MODE_MATCH && !score.over && tut < 0`。この間は G・1/2/3・N を受け付けず、お知らせ（`toast`）「試合中は変えられません（Esc → 選手と試合）」を出す。
  V・F（球出し）は試合では意味がないので黙って無視。H（手がかり）は表示だけなのでそのまま
- 後で変えた：試合のモードでは、終わった後（結果の表の間）も G・1/2/3・N・V・F を効かせない（`matchLock = mode == MODE_MATCH && tut < 0`）。勝った後に G を押して練習に変わり、結果が消えたため。スロー・自動操作を「補助を使った」と数えるのは、今まで通り途中（`matchLive`）だけ
- `matchAssisted`：試合の途中でスロー（T）・自動操作（B）を入れた、メニューで難しさ（MI_STYLE）を変えた。やり直しで false に戻る。
  今は結果の表の下の案内に「補助を使った試合」と出すだけ。後で記録（F01）を作るときに、この試合を記録から外すのに使う
- 売る版（`SALE_ONLY`）は試合中のスローなし、大会の試合中は自動操作なし
- 画面下の案内は、試合の途中は「Esc：メニュー」だけ

## 7. ボディショット：体に当たったら打った方のポイント（physics.c・main.c・ai.c）

現実のルール（ITF 規則 24：生きている球が体・服に触れたら、触れた方の失点）に合わせる。試合・バトル・リターン練習に効かせる。ラリー練習とサーブ練習は点を数えないので入れない。

**判定の入り口（どこに当たった扱いにするか）**
- 体＝足元 `pos` を中心にした鉛直の円柱。半径 `BODY_HIT_R` 0.24m（肩幅の半分＋球の半径）、高さ 0〜身長（`BodyTop`：`PersonaHeight` から。背の高い選手ほど当たる範囲が高い）
- 腕・ラケットは入れない：ラケットに当たった球は打ち返したのと同じ（今まで通り `EvaluateContact` の仕事）
- しゃがみ（Q）：円柱が `BODY_CROUCH_K`（35%）低くなる。ネット前で顔の高さの球をよけられる
- 調べ方：`BodyShotHit(a, b, feet, r, yLo, yHi, &at)`。物理の 1 ステップ（1/240 秒）の球の動きを線分として、円柱と交わるかを見る（速い球でもすり抜けない。
  前のバトルは 1 フレームに 1 回の点の判定だったので、速い球はすり抜けていた）。`at` は円柱に入った点
- バトルは今まで通り広い：半径 `BATTLE_BODY_R` 0.40m、高さ 0.3〜1.9m（腰から頭）

**バウンドの前後**
| 球の状態 | 体に当たったら |
|---|---|
| ノーバウンド | 打った方のポイント。アウトになる球でも（相手がコートの外に立っていても） |
| 1 バウンド目がイン、2 バウンド目より前 | 打った方のポイント（どうせウィナーになる球を、早く終わらせるだけ） |
| 1 バウンド目がアウト・ネット | 判定しない（その時点でポイントは終わっている） |
| ネットに当たって止まった球（`hitNet`） | 判定しない |
| サーブ、バウンド前 | サーバーのポイント（フォルトになる球でも）。サーブの統計は「入った」に数える |
| サーブ、ネットに触れて（`netCord`）バウンド前に当たった | レット（同じ番目のサーブを打ち直す） |
| サーブ、バウンドしてインの後 | サーバーのポイント（返されなかったサーブ） |

**詰まって打つ（打つ構えなら、体の前で振る）**
- 体に当たる前に、当たる側が「打つ構え」かを見る。構えなら、球が円柱に入った瞬間にその場で振らせる。当たればラリー続行（質は低い）、空振りなら体に当たった
  - AI・自動操作：`planned`（打つ計画がある）なら `swingAge` を今にして、同じステップの AI のスイングで振る（`bodyTry`）
  - 自分：押して溜めている（`chargingShot`）なら離したことにし、振る瞬間を待っている（`swingQ`）なら今にする。
    自分の振りは「前のフレームの球の動き」から打点を選ぶので 1 フレーム待つ（`bodyPend`）。待つ間、球は円柱に入った点で止める（その後ろへは進めない）
  - 振ろうとしていなかったら、すぐ体に当たった
- 理由：AI の立ち位置のずれ（EASY は 0.55m）で、打つつもりで球の通り道に立つことがよくある。そのまま体に当てると、AI 同士で EASY のポイントの 13〜19% がボディショットになった（現実ではほぼない）。
  現実の選手も、体に来た球は詰まりながら打つ
- バトルは詰まって打たない（体に当てるのがモードの遊びなので、今まで通り）
- AI は見送るアウトの球が体（円柱＋15cm の余裕）に向かってくるとき、横へ `BODY_DODGE`（0.75m）よける（`AiPlan` の見送りの所）

**当たった後**
- 球は手前に落ちる死んだ球にする（`BodyDeflect`：速さを 12% にして上へ 0.8m/s、`bounces = 3` で以後のバウンドの音・目印・判定を出さない）
- 統計：`endKind = 5`、ウィナーに数える（エースには数えない）。サーブなら「返されなかったサーブ」。matchlog.csv の end_kind は `body_shot`（前はバトルのボディショットが `error_out` と書かれていた）
- テロップ（TL）：「○○ body shot」、サーブなら「○○ serve hits the receiver」。鈍い音、観客の「おお」、お知らせ「ボディショット：○○ が手を上げて謝る」（ネットインと同じ礼儀）
- バトル：今まで通り、当たった方は倒れて画面が赤く光り、体力が 24 減る

**数字**（`make sim`、各 300 ポイント。sim も同じ判定・同じ詰まり打ち）
- ボディショットで終わるポイント：ハード 0.0%／0.0%／0.0%、クレー 0.7%／0.0%／0.0%、芝 1.3%／0.3%／0.3%（EASY／NORMAL／PRO）。
  ※ この数字は計測ツールの誤り（13 章：AI がバトルのように 2 割で体を狙っていた）の上のもの。直した後は 0〜0.7%
- ラリーの長さ・サーバーの勝率などは、入れる前と乱数のぶれの範囲で同じ

## 8. ラリーの集計の確認と、ポイントごとの記録の設計（実装は次回）

### 8a. 試合後の「平均のラリー」に、sim の 30 秒打ち切りは混ざっていない（確認だけ、直すものなし）

- 表の値は `ms[0].rallyTotal / ms[0].rallyPoints`。足すのは main.c のポイントが決まった所（`winner >= 0` のブロック）だけで、`rallyHits`（サーブで 1、打つたびに +1）をそのまま足す
- 本体のポイントに時間の打ち切りはない。30 秒で打ち切るのは `tools/ai_vs_ai.c` の `for (f < 60*30)` だけで、本体のコードからは使われていない（改善レビュー D02 の問題は sim だけ）
- matchlog.csv の `rally` 列と `tools/analyze_match.py` も、決着したポイントの打数をそのまま使っている
- 平均に入らないポイント（意図どおり）：ヒンドランス（カモン）で相手に与えたポイント、ラケット・ボールの乱用のポイントペナルティ、レット。
  ヒンドランスは打ち合いの途中で切れたポイントなので、8b の記録では「ペナルティ」として打数を残し、平均には入れない、と決めておく

### 8b. ポイントごとの記録（人間のラリーを細かく解析するため）

**今の記録で足りないこと**
- `PlayLog plog`（振り・空振り・早い／遅い・足／手）は**セッションの合計**で、練習と試合が混ざる。どのポイントの、どの球のことかがわからない
- `MatchStats ms` と `mst` は試合の合計だけ。ポイントごとの「何打目で、誰の、どんなミスで終わったか」がない
- playlog.csv・matchlog.csv は 1 球ごとに細かいが、**開発版だけ**（売る版は書かない）で、ファイルを後で集計する前提。試合の直後に画面で使えない
- 自分が失点したとき、それが「ミス（早い・遅い・位置）」「空振り」「届くのに見送り」「届かない」「体に当たった」のどれかが、ポイントと結び付いていない

**作るもの：1 試合分のポイントの記録をメモリに持つ（売る版でも）**

```c
// game.h
typedef enum {                  // ポイントの終わり方
    PE_ACE,                     // サービスエース（触れなかった）
    PE_SERVE_WINNER,            // 返されなかったサーブ（触ったが入らなかった・届かなかった）
    PE_WINNER,                  // ウィナー（2 バウンド）
    PE_BODY,                    // ボディショット
    PE_ERROR,                   // ミス（ネット・アウト）。どちらのミスかは ender
    PE_DOUBLE_FAULT,
    PE_PENALTY                  // ヒンドランス・ポイントペナルティ（打ち合いの結果ではない）
} PointEnd;
typedef enum { PERR_NONE, PERR_NET, PERR_LONG, PERR_WIDE } PointErr;          // ミスの種類。LONG/WIDE は Ball.lineAxis（1 = 縦の長さ、0 = 横）
typedef enum {                  // 自分の失敗の原因（自分がミス・失点したときの、自分の最後の球）
    YC_NONE,                    // 自分の失敗ではない（相手のミス、自分のウィナーなど）
    YC_EARLY, YC_LATE,          // 振るのが早い／遅い（いい当たりの瞬間から ±25ms より外）
    YC_POSITION,                // 立ち位置（その位置で一番よく振っても質 40% 未満）
    YC_SHOT,                    // 当たりは悪くない（タイミング・位置とも合格）のに入らなかった：狙い・溜め・球種の問題
    YC_WHIFF,                   // 空振り（MissReason は lastMiss に）
    YC_NO_SWING,                // 届くのに振らなかった
    YC_UNREACHED,               // 届かなかった（足・反応）
    YC_BODY                     // 体に当たった
} YouCause;

typedef struct {
    // いつ（ポイントの前の状態）
    uint8_t  set, gamesYou, gamesAi, ptsYou, ptsAi;   // ptsは 0,1,2,3…（タイブレークはその点）
    bool     tiebreak, breakPoint, gamePointYou;      // 大事さの区別（F10・H01 で使う）
    float    importance;                              // gPointImportance
    uint8_t  server;                                   // 0 = 自分、1 = AI
    uint8_t  serveNo;                                  // 1 / 2（このポイントが入ったサーブの番目。ダブルフォールトは 2）
    // どう続いたか
    uint8_t  shots;                                    // 打数（サーブも 1）＝ rallyHits
    uint8_t  youShots;                                 // そのうち自分の打数
    bool     youNet, aiNet;                            // ネットに出た（サービスラインより前）
    // どう終わったか
    uint8_t  winner;                                   // 0 / 1
    uint8_t  ender;                                    // 最後に打った方（ミスなら、ミスした方）
    uint8_t  end;                                      // PointEnd
    uint8_t  err;                                      // PointErr（end == PE_ERROR のとき）
    bool     forced;                                   // 強いられたミス（ms.unforced と同じ決まりの逆：速い球・飛びつき・遠い）
    float    outCm;                                    // アウトの距離
    // 自分の最後の球（自分が失点したときに一番大事）
    uint8_t  cause;                                    // YouCause
    uint8_t  lastType, lastMiss;                       // ShotType、MissReason
    bool     lastVolley, lastReturn, lastStretch;
    float    lastQ, lastBestQ, lastInKmh;              // 当たりの質、その位置での最高の質、来た球の速さ
    int16_t  lastOffMs;                                // プラス＝遅い
    bool     autopilot;                                // 自動操作で打った球がある（F10・記録では数えない）
} PointRec;

#define PREC_MAX 512                                   // 5 セットでも足りる
typedef struct { int n; PointRec p[PREC_MAX]; } MatchRecord;
```

- サイズは 1 ポイント約 40 バイト、1 試合 20KB。保存はしない（試合が変わるまでメモリに置く）。開発版は matchlog.csv の point 行に列を足して書く（列が変わると古いファイルは自動で別名になる仕組みがすでにある）

**どこで書くか（main.c）**
| 時 | すること |
|---|---|
| ポイントの始め（`POINT start` のログの所） | `ptCur` を 0 で作り、スコア・サーバー・大事さを入れる。`ptYou`（自分の最後の球）を空に |
| 自分が振った（`plog.swings++` の所、1976 行あたり） | `youShots++`。`ptYou` に球種・質・`bestQ`・`offMs`・`MissReason`・ボレー・リターン・伸びたか・来た球の速さ。原因は今の `plog` と同じ決まり（`offMs` ±25ms、`bestQ < 0.40` は位置、質が `bestQ` の半分以下はタイミング）|
| 自動操作の球 | `youShots++`、`autopilot = true` |
| 来た球を振らずに見送った（`LogTrackIncoming` で追跡が終わった所） | PlayLog に「最後の追跡」の結果（振ったか・届いたか・一番近い距離）を残す（`lastTrackSwung` など 3 つ足す）|
| ポイントが決まった（`winner >= 0`） | `end`・`ender`・`err`（`ball.result` と `ball.lineAxis`）・`forced`（今の `ms.unforced` の決まりと同じ）。自分が失点したら `cause` を決める（下）。`MatchRecord` に足す |
| ヒンドランス・ポイントペナルティ | `end = PE_PENALTY`、打数はその時点の `rallyHits` |
| フォルト・レット | 記録しない（1st がフォルトなら serveNo が 2 になるだけ）|
| やり直し（restart） | `rec.n = 0` |

自分が失点したときの `cause` の決め方：
1. 自分のミスで終わった（`end == PE_ERROR && ender == 0`）：最後の球の原因（早い・遅い・位置）。どれでもなければ `YC_SHOT`
2. 相手に決められた（ウィナー・エース・返されなかったサーブ）：振った → 空振りなら `YC_WHIFF`。振らなかった → 届いたなら `YC_NO_SWING`、届かないなら `YC_UNREACHED`
3. ボディショットで失点：`YC_BODY`
4. ダブルフォールト：`YC_NONE`（サーブは別に数える）

**F10（今日のコーチ）が使う形**

改善レビューの F10 は「セッションの合計の差」（`CoachSnap` の引き算）で作る案だったが、この記録があれば試合のポイントだけから作れる（練習が混ざらない、自動操作の球を除ける）。
集計は 1 つの関数にまとめ、F10 はこの集計だけを見る：

```c
typedef struct {
    int points, won, autopilotPts;
    // 自分のミスの内訳（ポイントを終わらせたミス）
    int err[4];                    // PointErr ごと（[0] は使わない）
    int errForced, errUnforced;
    int cause[9];                  // YouCause ごと（失点の原因）
    // 振り（このポイントの記録の中の自分の球。playlog と同じ分け方）
    int swings, early, late, onTime, pos, timing, whiffs;
    // 場面ごとの取った数：[場面][0=ポイント数,1=取った数]
    int byLen[4][2];               // 打数 1〜2（サーブ・リターン）、3〜4、5〜8、9 以上
    int asServer[2][2];            // [serveNo-1]
    int asReceiver[2][2];          // 相手の 1st / 2nd
    int big[2];                    // 大事なポイント（importance >= 1）
```

## 9. ネットタッチ（文字どおり触れたら）と、ネットをすり抜けない（main.c・ai.c・render.c）

最初は「体の中心がネットから 40cm より近いと失点」にしたが、触れていないのに失点になると不評だったので、文字どおり触れたときだけにした。

- 止める所：自分は体の中心がネットから `NET_BODY_R`（0.20m：体の前後の厚みの半分、つま先まで）の所。そこで体がネットに触れている。
  AI・自動操作は `AiUpdate` の最後で `NET_AI_KEEP`（0.45m）より前へ出ない（走ってネットに触れない）。ネットの幅（ポストの外 0.5m まで）の所だけ
- 失点になる触れ方（ルール「ネットタッチ」があるとき。試合とバトルの `PH_PLAY` で、ポイントがまだ決まっていないとき）
  1. 体：体の中心がネットから `NET_BODY_R` 以内（＝止まる所まで来た）
  2. 伸びた体：打った瞬間に、伸びきったときの腰の位置（`LungeRootWorld`）がネットから `NET_BODY_R` 以内
  3. ラケット：打った瞬間に、球がネットから `NET_RACKET_R`（0.13m：ラケットの面の半分）より近い。面の端がネットを越える
  - 2・3 は打った瞬間に `NetTouchAtContact` で調べて `netTouchWho`・`netTouchHow` に覚え、その後のポイントの判定で失点にする（ポイントの準備で消す）。
    自分・AI・自動操作の打球の全部で調べる
- 伸びて取る姿勢：腰を球の方へ出す量の式を `LungePoseOf`（render.c）にまとめ、描く `DrawFigureBody` と判定の `LungeRootWorld` で同じ式を使う（見た目と判定がずれない）
- 見た目：伸びて取る間も、腰はネットから `NET_BODY_R` の手前で止める（めり込まない）。腕とラケットは少し届かなく見えることがある
- ルールが「なし」なら、ネットで止まるだけで失点にはしない
- 現実のルールとの違い：現実では、自分の側で打った後の振り抜きでラケットがネットの上を越えるのは反則ではない。ここでは「打つときにラケットがネットを越える」を、球がネットのすぐ近く（13cm）で打ったときとしている（振り抜きは見ていない）
- `endKind = 6`、記録の end_kind は `net_touch`、テロップは「net touch」と「racket over the net」。統計はウィナーにもミスにも数えない
- AI 同士（`make sim`）の数字は、入れる前と同じ
